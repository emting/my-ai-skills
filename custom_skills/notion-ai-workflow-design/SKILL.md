# Notion AI 工作流設計 Skill

> **定位**：協助判斷一個工作流程應該沉澱成 Notion 文件、Skill、資料庫自動化、N8N 流程或 AI Agent，並把它設計成可重複使用的 Notion AI 工作流。

## 使用情境
- 想把一段重複工作變成 Skill。
- 不確定某件事該用 Notion AI、N8N、資料庫自動化還是 Agent。
- 想建立團隊知識庫、How-to、Why 文件或 SOP。
- 想設計 Notion 資料庫、Dashboard、Instruction 或 Skill 的使用邊界。
- 想把會議紀錄、語音筆記或課程筆記轉成可重複工作法。

## 核心判斷
| 類型 | 適合情境 | 不適合情境 |
|---|---|---|
| How-to 文件 | 固定步驟、教新人怎麼做 | 需要價值判斷的任務 |
| Why 原則文件 | 品控、價值觀、判斷標準 | 單純操作步驟 |
| Skill | 重複使用的 Prompt、流程、風格、判斷框架 | 一次性任務 |
| Notion 資料庫自動化 | Notion 內部屬性變更、通知、簡單固定規則 | 需要複雜推理 |
| N8N | 跨工具固定流程、每次答案應一致 | 需要語意判斷與個人價值觀 |
| AI Agent | 需要推理、判斷、搜尋、整合與不固定輸出 | 完整複製原文、不能容忍資訊損失 |

## 工作流設計流程
1. **任務辨識**：這是一次性任務，還是重複流程？
2. **文件類型判斷**：是 How-to、Why、Skill 還是資料庫？
3. **自動化層級判斷**：資料庫自動化、N8N、AI Agent 或人工處理。
4. **觸發條件設計**：什麼時候應使用這個流程？
5. **輸入與輸出定義**：需要哪些資料，產出什麼格式？
6. **風險與成本評估**：是否會有資訊損失、成本過高、權限不足或誤判？
7. **沉澱成 Skill**：加入 description、流程、輸出格式與品質標準。

資訊不足時（例如只說「自動化 onboarding」）：先問最小必要問題——頻率、觸發、資料欄位、權限與完成定義；涉及個資或權限時先停下確認。

## 品質標準
- 不把所有東西都做成 Agent；固定流程優先用固定工具。
- 需要完整原文保真時，不用 AI Agent 重新整理。
- Skill 必須有明確 description，避免 AI 找不到或誤用。
- 團隊協作用 Notion 作為知識載體；個人過程筆記避免混入團隊決策資料。

## Opus 5 世代模型校準
> 本 Skill 是**決定其他 Skill 該不該存在**的上游工具。模型世代換了，判斷門檻也要跟著換。

### 判斷表的門檻往「Agent」方向移了一格
新世代模型的指令遵循與長流程穩定度大幅提升，過去因為「模型會迷失」而傾向 N8N 硬流程的任務，現在可以重新評估。但**判準不變**：每次答案應該一致的固定流程，還是用固定工具；需要語意判斷的才給 Agent。不要因為模型變強就把一切都 Agent 化。

### 新增一個判斷問題：這件事需要幾個 Agent？
設計工作流時預設**一個 Agent**。只有任務夠大、彼此獨立且可真實並行時才拆成多個。幾次工具呼叫就能完成的事不要拆，**也不要設計「第二個 Agent 負責複核第一個 Agent」的架構**——這是舊世代的補強做法，現在只是成本與延遲倍增。

### Skill 草稿要從比你覺得安全的更少結構開始
第 4 節產出 Skill 草稿時，不要一開始就寫上多階段流程、狀態檔、進度儀表板、逐步確認。**先給最少結構，實際跑過失敗了再把規則加回來**。過去的 Skill 工程在教怎麼加 scaffolding，新世代要練的是怎麼減。

### 品質標準要寫進去的兩段
產出 Skill 草稿時，預設把這兩項寫進「品質標準」：
- **輸出長度**：篇幅要匹配任務需要，不用填充段落、重複摘要或樣板小標充數；未指定長度時先給高層次結論。
- **範圍鎖定**：交付被要求的範圍；例行判斷自己做，只有不同解讀會導致做出實質不同的東西時才回頭確認。

### 不要再寫「輸出前逐項自我檢查」
這是舊世代最常見的 Skill 模板句。新模型已內建自我修正，疊加只拉高成本。例外：若驗證步驟的目的是**留下給人審核的痕跡**（合規、對外發佈、金流），則保留並明確標示為「人工審核關卡」。

## 標準執行契約

### 觸發與輸入

使用者明確要求此主題，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入與授權，標記缺口、敏感資料與可能的外部依賴。
2. 依本技能的核心流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，並列出引用、未驗證事項、風險與需要人工決策的節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

### 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式或尚待確認的項目。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

### 安全與人工核准

目前風險等級：**high**。需要人工確認。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。
- 涉及外部資料時記錄來源、擷取時間與查證限制；將可觀察事實、推論與建議分開呈現。
- 此技能只提供分析、草稿與驗證建議，不代表法律、財務、醫療、投資或營運承諾；高風險決策須由合適的人員覆核。

### 禁止用途

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。
- 不得在沒有明確批准、完整上下文與可回溯驗證的情況下執行高影響外部操作。

### 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，先停止執行高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露或輸出無法驗證，保留已完成的安全分析，暫停後續動作並要求人工判斷。

## 關聯技能

本技能與 無 有功能相近或可互補的既有技能；選擇時以使用者明確需求、資料來源與權限邊界為準，不要平行重複執行相同的高影響操作。
