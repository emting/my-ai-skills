# Warp AI Multi-Agent 戰情室 Skill

> **定位**：將 Warp Launch Configurations 變成 AI Multi-Agent 戰情室，一鍵啟動多個 CLI Agent 面板，適合本機多代理協作、重構、研究與執行監控。

## 使用情境
- 需要同時開啟 Amp、Codex、Gemini、Warp Agent 或 Log Pane。
- 需要固定四分欄工作區，避免每次手動配置。
- 需要跨裝置同步 AI 工作站配置。
- 需要處理多 CLI 工具的快捷鍵衝突與啟動驗收。

## 前置需求
- Warp 支援 Launch Configurations。
- 已安裝並可在 terminal 呼叫：
  - Amp：大型重構與多檔編輯。
  - Codex CLI：精準腳本生成。
  - Gemini CLI：長文本與多模態分析。
- 若使用右下角 log pane，需有實際 log 路徑或替代啟動命令。

## 預設配置
```yaml
name: AI Multi-Agent
windows:
  - tabs:
      - title: AI Command Center
        layout:
          split_direction: horizontal
          children:
            - layout:
                split_direction: vertical
                children:
                  - command: "amp"
                  - command: "codex chat"
            - layout:
                split_direction: vertical
                children:
                  - command: "gemini"
                  - command: "echo '🟢 Ready — Warp Agent / Log Pane'"
```

## 主流程
1. 檢查 CLI 工具是否可直接呼叫。
2. 建立 Warp Launch Configuration。
3. 貼入 YAML 並命名。
4. 一鍵啟動四分欄。
5. 檢查每個面板是否正確啟動。
6. 若快捷鍵衝突，調整 Honor Terminal ESC Sequences 與 Keybindings。
7. 若需跨裝置，存入 Warp Drive。

## 固定輸出格式
輸出為單一、可直接貼入 Warp 的有效 YAML 區塊，加上短清單：

1. **目標配置**：左上／左下／右上／右下各放什麼。
2. **YAML**：完整、可解析的單一 YAML 區塊（不含佔位符）。
3. **驗收清單**
   - [ ] 每個 CLI 可呼叫
   - [ ] Warp 成功載入配置
   - [ ] 四分欄位置正確
   - [ ] 快捷鍵無衝突
   - [ ] 右下角 pane 有實際用途
4. **排錯**

## 品質標準
- YAML 必須是可貼入編輯器的完整區塊。
- 右下角不要只放無意義 clear，應放狀態提示、log 或控制台。
- 每個 pane 的用途要明確。
- 啟動配置前先確認工具已安裝；實際套用前先在測試環境解析 YAML 並驗證每個 CLI 命令。

## Opus 5 世代模型校準
### 四分欄不等於四個 Agent 都要動
這是本 Skill 在新世代最容易踩的坑。四分欄是**你的工作台佈局**，不是「每個任務都要四個 Agent 一起上」的指令。委派門檻：
- 只有任務夠大、彼此獨立且可並行時才分給多個 Agent，例如跨多檔案的大範圍調查。
- 幾次工具呼叫就能完成的事，在一個面板做完就好。
- **不要開第二個 Agent 來複核第一個 Agent 的輸出。** 這是舊世代的補強做法，在新模型上只是成本倍增。多面板的價值在**平行跨範圍**，不在互相監視。

### 右下角 pane 的新用途
原本建議放狀態提示或 log。新世代下更值得放的是 **token／成本監控**：多 Agent 並行時成本上升很快，看得到才控得住。

### 成本用 effort 控，不要關 thinking
各 CLI Agent 若支援 effort 或類似強度參數，用它來調成本。**不要用關閉 thinking 省錢**：那可能造成工具呼叫外洩成純文字與內部 XML 標籤外洩，在多面板環境下特別難除錯。舊模型調好的 effort 預設值換新模型後要重新掃一次，不要直接沿用。

### 驗收清單是給人勾的
驗收清單是你自己確認環境用的，保留。但不要要求模型「輸出 YAML 前再自我檢查一次」。

### 輸出長度
這是配置型 Skill，輸出應該就是 **YAML 加短清單**。不要附送終端機工作流的背景介紹或各 CLI 工具的優缺點比較，除非你問了。

## 標準執行契約

### 觸發與輸入

使用者明確要求此主題，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入與授權，標記缺口、敏感資料與可能的外部依賴。
2. 依本技能的核心流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，並列出引用、未驗證事項、風險與需要人工決策的節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

### 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式或尚待確認的項目。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

### 安全與人工核准

目前風險等級：**high**。需要人工確認。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。
- 涉及外部資料時記錄來源、擷取時間與查證限制；將可觀察事實、推論與建議分開呈現。
- 此技能只提供分析、草稿與驗證建議，不代表法律、財務、醫療、投資或營運承諾；高風險決策須由合適的人員覆核。

### 禁止用途

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。
- 不得在沒有明確批准、完整上下文與可回溯驗證的情況下執行高影響外部操作。

### 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，先停止執行高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露或輸出無法驗證，保留已完成的安全分析，暫停後續動作並要求人工判斷。
