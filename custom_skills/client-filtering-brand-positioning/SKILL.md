# 客戶篩選與品牌定位 Skill

> **定位**：協助使用者決定「要服務誰、不服務誰」，用市場規模、品牌定位與客戶期待管理，篩選真正適合的客戶。

## 使用情境
- 客戶意見很多，使用者不知道該聽誰的。
- 產品有人喜歡、有人不喜歡，不知道要改產品還是篩客人。
- 品牌定位模糊，導致期待值失控。
- 想設計有限客製化，而不是被每個客戶牽著改。

## 不適用情境
- 使用者想滿足所有人。
- 目前沒有任何客戶反饋或市場資料。

## 公平與合規閘門
篩選理由限於服務能力、需求適配、可交付性與合約條件；不得以受保護身分（如年齡、族裔、性別、宗教、身心障礙）作為排除依據。

## 食譜式目標
| 項目 | 定義 |
|---|---|
| 輸入 | 客戶反饋、產品特色、品牌定位、客群規模 |
| 輸出 | 客群分類、服務對象、拒絕對象、期待管理方案 |
| 數量 | 至少 2 類客戶、1 個核心定位、3 條篩選規則（下限不是配額） |
| 格式 | 表格 + 門口標示 + 客製化邊界 |
| 驗收 | 能知道該改產品、改溝通或改客戶 |

## 核心流程
1. **蒐集反饋**：喜歡什麼、不喜歡什麼、為什麼。
2. **分類客戶**：喜歡你／不喜歡你；高價值／低價值；符合定位／不符合定位。
3. **判斷市場規模**：喜歡你的人是否足夠養活生意？
4. **對照品牌定位**：你想成為大眾品牌、小眾品牌、高端品牌或效率品牌？
5. **選擇服務對象**：不是所有反饋都要採納。
6. **彰顯特色**：在入口、文案、報價、簡報中先說清楚你是誰。
7. **有限客製化**：提供可選範圍，但不讓客戶重寫你的產品。
8. **建立推薦循環**：讓喜歡你的客戶帶來同類客戶。

## 0/1 測試
| 測試 | 通過條件 |
|---|---|
| 客群可分 | 至少分出喜歡與不喜歡兩類 |
| 定位明確 | 能說出服務誰與不服務誰 |
| 規模檢查 | 有判斷客群是否足夠大 |
| 期待可控 | 有前置說明或篩選機制 |
| 客製有限 | 有明確可客製與不可客製 |

## Opus 5 世代模型校準
### 沒有反饋資料就不要編客群（本 Skill 最大風險）
客群分類表有「規模」與「價值」兩欄，模型很容易在沒有真實客戶資料時寫出看起來很具體的估算。規則：**沒有實際反饋或銷售資料時，這兩欄寫「需盤點」並列出要從哪裡拿資料**，不要給數字。客群規模判斷錯了，後面整張定位都是錯的。

### 反饋盤點要兩段式
不要下「只列最重要的客戶反饋」。新世代模型會照字面執行，把低頻但高價值客戶的意見先刷掉——而那常常正是定位訊號。正確做法：第一輪**全量**列出所有反饋並標來源客群，第二輪再用「是否符合定位 × 客群價值」分類。頻率高不等於重要。

### 數量是下限不是配額
若只有兩條真正守得住的規則，就給兩條。篩選規則湊數量等於寫了不會執行的規則，反而讓真規則失效。

### 「不服務誰」要用正面示範寫
不要只列拒絕條件，直接給一句**你會真的說出口的門口標示句**。例如不寫「不接受臨時插班」，而寫「我們採固定班表，這樣老師才能掌握每個孩子的進度」。同一件事，後者才是品牌。

### 0/1 測試是交付規格
五項測試保留，定位是**你驗收用的**，不是要模型輸出前自我檢查一遍。

### 輸出長度
篇幅集中在第 3 節定位判斷與第 5 節下一步。不要附送品牌定位理論、STP 框架介紹或產業概述。

## 標準執行契約

### 觸發與輸入

使用者明確要求此主題，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入與授權，標記缺口、敏感資料與可能的外部依賴。
2. 依本技能的核心流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，並列出引用、未驗證事項、風險與需要人工決策的節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

### 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式或尚待確認的項目。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

### 安全與人工核准

目前風險等級：**high**。需要人工確認。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。
- 對個人、客戶、學生、財務、合約或私有資料採資料最小化；輸出前遮罩識別資訊，避免複製原始敏感資料。
- 此技能只提供分析、草稿與驗證建議，不代表法律、財務、醫療、投資或營運承諾；高風險決策須由合適的人員覆核。

### 禁止用途

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。
- 不得在沒有明確批准、完整上下文與可回溯驗證的情況下執行高影響外部操作。

### 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，先停止執行高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露或輸出無法驗證，保留已完成的安全分析，暫停後續動作並要求人工判斷。
