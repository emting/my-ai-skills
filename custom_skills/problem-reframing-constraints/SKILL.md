# 問對問題與限制條件 Skill

> **定位**：協助使用者在急著找解法前，先問對問題。透過現況分析、目標設定、障礙與限制條件，將模糊困境拆成可處理的核心問題。

## 使用情境
- 團隊討論很久，但每個人其實在解不同問題。
- 使用者手上有很多方案，卻不確定真正目標。
- 任務卡住，不知道是障礙、限制條件還是目標錯了。
- 需要把複雜問題拆到可以行動。

## 不適用情境
- 使用者已經有清楚目標、限制與方案，只需要執行。
- 問題涉及專業診斷，例如法律、醫療、心理治療，需專家介入。

## 食譜式目標
| 項目 | 定義 |
|---|---|
| 輸入 | 現況、困擾、期望結果、已知限制、資源 |
| 輸出 | 正確問題、主要障礙、限制條件、解法方向 |
| 數量 | 1 個核心問題 + 最多 3 個可行方案（上限不是配額） |
| 格式 | 問題拆解表 |
| 驗收 | 能知道接下來要解哪個問題 |

## 核心流程
1. **現況分析**：有哪些地方怪怪的？
2. **目標設定**：理想狀態是什麼？
3. **限制條件**：哪些東西不能改、難以改或成本太高？
4. **主要障礙**：哪些東西可被克服，而且最影響目標？
5. **問題重寫**：把原本模糊問題改成精準問題。
6. **提出方案**：只針對主要障礙設計方案。
7. **減法檢查**：刪掉無關、無法控制或不影響目標的支線。

## 固定輸出格式
```markdown
## 問對問題與限制條件分析

## 1. 原始問題
- 使用者原話：
- 看起來想解決：
- 可能真正想解決：

## 2. 現況分析
| 現象 | 為什麼怪 | 證據 |
|---|---|---|

## 3. 目標設定
- 理想狀態：
- 成功指標：
- 不做會怎樣：

## 4. 障礙與限制
| 項目 | 類型：障礙／限制 | 是否可改 | 處理方式 |
|---|---|---|---|

## 5. 核心問題
請把問題改寫成：

## 6. 解法方向
1. 
2. 
3. 
```

## 0/1 測試
| 測試 | 通過條件 |
|---|---|
| 目標明確 | 有理想狀態 |
| 限制列出 | 至少列出 3 個限制（沒講的標「待確認限制」） |
| 障礙可控 | 主要障礙可被行動影響 |
| 問題重寫 | 原問題被改成可解問題 |
| 方案對焦 | 方案直接對應主要障礙 |

## Opus 5 世代模型校準
> 本 Skill 本身就是「範圍鎖定」的工具：第 7 步的**減法檢查**與新世代的核心原則完全一致。

### 排除動作不能提前
第 6 步「只針對主要障礙設計方案」與第 7 步減法都是正確的，**但它們是第二輪動作**。新世代模型對這類指令照字面執行，容易在第 2、4 步就提前自我審查，把看起來不重要的現象與障礙先刷掉——而問對問題的價值，往往就藏在一開始看起來不相關的那一項。規則：
1. 第 1–4 步：**全量展開**。現象、障礙、限制先全部列進表格，包括你自己覺得不重要的。
2. 第 5–7 步：**再收斂**。這時才減法、才重寫成單一核心問題。

### 限制條件不要靠推測補齊
「至少列出 3 個限制」是下限，不是要你湊。使用者沒講的預算、人力、時程，直接列成「待確認限制」並問出口，**不要自己假設一個合理數字**。限制條件假錯了，後面所有方案都歸零。

### 模糊不代表要回問
例行判斷自己做，**只有不同解讀會導致做出實質不同的東西時才回頭確認**。若一個問題問完不會改變核心問題的寫法，就自己假設並標明假設，繼續往下。

### 輸出長度
本 Skill 的價值在**第 5 節那一句重寫後的問題**。前面四節是推導過程，簡潔即可；若整件事用五行就能講完，就用五行。

## 啟用提示詞
請啟用「問對問題與限制條件 Skill」。任務：幫我釐清以下困境真正要解的問題，區分現況、目標、障礙、限制條件與可行解法。

## 標準執行契約

### 觸發與輸入

使用者明確要求此主題，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入與授權，標記缺口、敏感資料與可能的外部依賴。
2. 依本技能的核心流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，並列出引用、未驗證事項、風險與需要人工決策的節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

### 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式或尚待確認的項目。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

### 安全與人工核准

目前風險等級：**low**。預設可先產出分析或草稿，但仍不得代替使用者做外部高影響決策。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。

### 禁止用途

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。

### 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，先停止執行高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露或輸出無法驗證，保留已完成的安全分析，暫停後續動作並要求人工判斷。

## 關聯技能

本技能與 無 有功能相近或可互補的既有技能；選擇時以使用者明確需求、資料來源與權限邊界為準，不要平行重複執行相同的高影響操作。
