# 說人話｜繁體中文去 AI 味與台灣在地化 Skill

> **核心原則：先保事實，再去 AI 味，最後才加人味。** 這是校稿 Skill，不是萬用寫作器，也不是拿來規避 AI 偵測器。

## 專案研究摘要
本 Skill 研究並重新整理自 Raymond Hou 的開源專案 speak-human-tw（MIT License，https://github.com/Raymondhou0917/speak-human-tw）。原專案 v1.4.0 專為台灣繁體中文設計，涵蓋 38 種 AI 寫作痕跡、60+ 組台灣用語校正、五種使用情境、保護清單、兩輪人工確認，以及 SF／SNF 誤殺防護評測。

最有價值的是四層治理：
1. **模式層**：辨識內容、句式、版面、溝通殘留與工具痕跡。
2. **情境層**：社群、電子報、銷售頁、客服與辦公文書採不同力度。
3. **保真層**：價格、數字、專名、連結、引言、承諾先鎖定，改後逐項回讀。
4. **人審層**：預設先提案、後改稿；未經確認不覆蓋原稿。

## S1｜觸發條件
### 應觸發
- 「去 AI 味」「說人話」「這段好 AI」「改自然一點」
- 「幫我潤稿，但不要有機器感」
- 「校對一下再發」「改成台灣人會說的繁體中文」
- 要檢查電子報、社群貼文、銷售頁、課程文案、客服回信、簡報、公告或 Email 的語感

### 不應觸發
- 逐字翻譯
- 事實查核（可疑引用只標記，不代查）
- 模仿特定個人或品牌 voice（改用 `personal-voice-modeling-style-guard`）
- 從零創作文案、故事或個人經歷
- 程式碼、log、設定檔等非自然語言內容

**一句話定位：本 Skill 只負責把稿子洗乾淨，不替作者注入人設。**

## S2｜輸入契約
**必要輸入**：待檢查或改寫的完整文字。

**建議輸入**：發布情境（社群／電子報／銷售頁／客服／辦公文書）；目標讀者與發布平台；改寫力度（輕／中／中偏重）；是否允許刪句、併句、重排；直接套用或先列問題清單；不能動的專名、數字、條款與原話。

**資訊不足時**只問會改變結果的最少問題：「這段文字會在哪裡被讀者看到？」若只是一般校對且情境可從內容判斷，不重複追問。沒附文字時只索取原文，不自行創作。

## S3｜執行步驟
### Step 1｜判斷情境與力度
| 情境 | 力度 | 主要目標 |
|---|---|---|
| 社群貼文 | 輕 | 保留口語、玩梗、自嘲，只砍明顯套話與 emoji 轟炸 |
| 電子報／部落格 | 中 | 保留故事與節奏，刪空話、導引句與段段總結 |
| 銷售頁／課程文案 | 中偏重 | 把浮誇形容詞換成具體賣點，但不削弱 CTA |
| 客服／學員回信 | 中 | 先回答、再說明、最後給下一步；保留責任與條款 |
| 簡報／公告／Email／報告 | 中 | 結論先行、刪避險墊片；正式語域仍保持正式 |

混合情境先定主情境，再讓局部段落套用自己的規則。

### Step 2｜建立保護清單
動筆前圈出並鎖定：
1. **價格與數字**：金額、折扣、優惠碼、日期、時間、人數、成效數據。
2. **專有名詞**：品牌、產品、課程、活動與平台名稱。
3. **網址與連結文字**：保留原連結；只移除 `utm_source=chatgpt.com` 等工具殘留。
4. **真實姓名與引號內原話**：逐字保留；錯字只提醒，不代改。
5. **承諾與條款**：退費、保固、免責、服務範圍只能調銜接，不能改意思。

### Step 3｜判斷改寫範圍
- **約 1000 字以下**：可提出刪句、併句、重排。
- **約 1000 字以上**：盡量逐句對應；空話可建議刪除，但要說明刪除不會少掉什麼資訊。
- 使用者要求「一句都別刪」：只做句內降調，不提整句刪除。

### Step 4｜依優先序清理
1. **先刪**：諂媚、對話殘留、免責墊片、通用正向結論、預告式導言、公式化開場。
2. **再具體化**：誇大意義、廣宣語氣、模糊歸屬、立場真空；沒有事實可補就刪或留作者佔位。
3. **再降格式**：粗體轟炸、emoji 堆疊、破折號過密、硬湊三段、無必要表格與編號。
4. **同步台灣在地化**：用語、量詞、標點、引號與翻譯腔。
5. **最後才加人味**：只能放大原文已有的觀點、反應、節奏、矛盾與口語，不可編造。

### Step 5｜38 種痕跡分類檢查
**A. 內容類（1–9）**：誇大意義與趨勢；過度強調媒體與關注度；空洞分析收尾；廣告宣傳語氣；模糊歸屬與無源權威；公式化前景段；正向籠統、均值回歸；幻覺引用；立場真空（「各有優缺點」「因人而異」卻沒有選擇條件）。

**B. 語言與句式類（10–21）**：系詞迴避（「作為」「扮演著角色」）；硬湊排比三段式；「不是 A，而是 B」「不僅⋯⋯更⋯⋯」過密；刻意換詞循環；虛假範圍（「從入門到精通」）；解說導引（「這意味著」「你會讀到一件事」）；勸誡反問收尾；說教式深度腔（「說到底」「本質上」）；金句／格言公式；假坦白鉤子（「說真的」「老實說」）；戲劇性短句轟炸；公式化開場（「在當今瞬息萬變的時代」）。

**C. 風格與版面類（22–29）**：檢查破折號、粗體、emoji、碎片化標題、列表、表格、首先／其次／最後與不自然 Markdown 密度。原則是**密度與內容支撐**，不是看到形式就一律刪。

**D. 溝通殘留類（30–36）**：「希望這對你有幫助」、頒獎式開場、罐頭總結、過度限定、知識截止免責、模板佔位字與預告式導言。

**E. 工具痕跡類（37–38）**：AI 來源參數、`turn0search` 類佔位碼，以及平台不支援的 Markdown 標記。

### Step 6｜台灣在地化
常見硬替換：
| 中國用語 | 台灣用語 |
|---|---|
| 視頻 | 影片 |
| 質量 | 品質 |
| 信息 | 資訊 |
| 網絡 | 網路 |
| 軟件／硬件 | 軟體／硬體 |
| 數據庫 | 資料庫 |
| 服務器 | 伺服器 |
| 屏幕／鼠標 | 螢幕／滑鼠 |
| 默認 | 預設 |
| 支持某功能 | 支援某功能 |
| 兼容 | 相容 |
| 反饋 | 回饋／意見 |
| 性價比 | CP 值 |
| 落地 | 執行／實作／真的做出來 |
| 賦能／閉環／抓手 | 不硬換同義詞，改寫成具體動作 |

標點與語感：
- 中文句子使用全形標點「，。：；！？『』「」（）」。
- 第一層引號用「」，內層用『』；書名與篇名用《》〈〉。
- 數字與單位用半形：42%、4,800 元、3/31。
- 中國平台專名、受訪者原話、作者刻意玩梗不改。

### Step 7｜保真回讀
逐項確認：五類保護項目都存在且逐字一致；原文每個事實、數字、判斷與行動都能追溯；沒有新增原文未提供的數字、來源、故事、立場或承諾；作者立場未翻轉或被稀釋；語域與情境一致。

### Step 8｜長文自評
長文、電子報與銷售頁用五個維度各 1–10 分：直接性、節奏、信任度、真實性、精煉度。35 分以下回頭修；35–44 分可用但再修最弱的 1–2 項；45 分以上可交付。此分數只評校稿品質，不宣稱能量化「人味」。

## S4｜安全閘門
### 預設採兩輪模式
**第一輪只提案，不改原稿。** 每個問題都要完整列出，不能用「其餘類似」省略：觸發位置、原句、為什麼要改、建議怎麼改。最後詢問：「以上 N 處有什麼地方是你覺得需要修改的嗎？」使用者回覆「都改」「只改 2、4、6」「第 3 條不要」後，第二輪才套用。沒有勾選的地方保持原文。

### 可跳過確認的情況
- 使用者明確說「直接改，不用先列清單」。
- 單次 CLI、CI、排程等非互動執行：直接套用，但事後逐條回報。
- 長期自動化整合前，先選擇「中途暫停確認」或「跳過確認、事後摘要」。

### 絕對禁止
- 為了具體而編造數字、來源、見證、故事或個人轉折。
- 把「標誌著」換成「象徵著」等換湯不換藥。
- 把正式公告、法務或客服條款硬改成聊天口吻。
- 削弱價格、期限、名額、退費或 CTA 的功能。
- 直接覆蓋檔案而未取得授權。

## S5｜輸出格式
### 模式 A｜預設審查清單
```text
1. 觸發位置：第 2 段，第 1 句
   原句：⋯⋯
   為什麼要改：公式化開場，前半句沒有這篇文章獨有的資訊。
   建議怎麼改：⋯⋯

以上 N 處有什麼地方是你覺得需要修改的嗎？
```
### 模式 B｜Annotation mode
使用者說「先標問題不要改」時，只列最重要的 1–5 點：問題類型、觸發位置、建議動作（刪除／改具體／降格式／補來源／不動）、是否建議改寫。不附完整改寫稿。

### 模式 C｜直接改寫或第二輪
輸出：套用使用者選定項目後的完整版本；3–5 條修改重點（需要時）；高風險保護說明，例如「退費條款與日期逐字保留」。

### 模式 D｜非互動事後摘要
```text
這次找到並修改了 N 處。

1. 原句：⋯⋯
   為什麼要改：⋯⋯
   改成了什麼：⋯⋯
```
### 特殊標記
- 缺作者事實：`（需作者補充：實際數字／例子／選擇理由）`
- 可疑引用：`〔需查證來源〕原句`

## S6｜失敗處理
| 狀況 | 處理方式 |
|---|---|
| 無法判斷使用情境 | 問一次「這段文字讀者會在哪裡看到？」 |
| 原文幾乎全是空話 | 刪除建議照列；需要內容處留下作者佔位，不自行補故事 |
| 只有文章節錄 | 以節錄為計數範圍，提醒全文再檢查密度規則 |
| 可疑數據或引用 | 保留原句並加 `〔需查證來源〕`，不代查、不代編 |
| 規則互相衝突 | 依序優先：事實正確 → 資訊完整 → 去 AI 痕跡 → 人味 |
| 可能是刻意修辭 | 檢查是否有具體事實、立場或情緒支撐；有就放行 |
| 使用者拒絕建議 | 保留原文，不辯論、不順便改其他地方 |
| 沒有發現問題 | 明確說「未發現需要修改的 AI 痕跡」，不要硬湊修改 |

## S7｜範例與模板
### 範例 1｜社群貼文
**原句**：🚀 重磅消息！這不僅是一堂課，更是一場思維革命。在這個快速變化的時代，掌握 AI 已成為不可或缺的能力。🔥

**審查**：emoji 密度過高；「不僅⋯⋯更⋯⋯」與「思維革命」只有形式，沒有具體內容；「快速變化的時代」是公式化開場。

**建議**：AI 寫作工作坊開放報名了。三個小時，會帶你完成語氣設定、改稿流程與內容自動化。（時數與課程內容必須由作者提供；沒有就標註待補。）

### 範例 2｜客服回信
**原句**：感謝您的來信，這真是一個非常棒的問題。建議您可以嘗試清除快取，或許能在某種程度上解決問題。希望這對您有幫助！

**建議**：作業上傳後看不到，通常是瀏覽器快取造成的。請先強制重新整理；還是看不到的話，改用無痕視窗登入。兩個方法都試過仍有問題，請回信附上截圖，我們從後台確認。

### 範例 3｜銷售頁的誤殺防護
**原句**：早鳥價 4,800 元（原價 6,800 元），輸入折扣碼 EARLY500 再折 500，只到 3/31 晚上 11:59。

**判斷**：不改。價格、折扣碼、期限與急迫感都是必要資訊。

### 範例 4｜立場真空
**原句**：兩種筆記法各有優缺點，適合的工具因人而異。

**處理**：（需作者補充：你實際選哪一個？使用多久？決定因素是什麼？）不可自行寫成「我最後選 Obsidian」，除非作者真的提供這個事實。

## 人味的正向目標
清掉 AI 痕跡後，只能沿著作者原有素材往以下方向拉：
- 對事實做出真實反應，而不只報告。
- 長短句交錯，讓節奏有變化。
- 允許某個作者最在意的點多講一點。
- 保留真實矛盾與想法轉變。
- 觀點文可適當用「我」。
- 社群與電子報允許不收尾、口語碎片與一點不完美。

**不要表演口語、表演不確定、硬造金句，或替作者發明人生。**

## 評測與驗收建議
原專案用兩類案例測試：**SF（Should Fix）**：該改的要命中；**SNF（Should Not Fix）**：有事實支撐的排比、來源明確的數據、金流條款、長文節奏句與專名不可誤殺。

每次版本更新至少加入：一個新命中案例；一個相似但不該修改的反例；一個保護清單回歸案例；一個「換湯不換藥」檢查。

建議驗收條件：所有保護項目 100% 保留；不新增任何原文沒有的事實；台灣用語與全形標點檢查完成；未授權時不直接改稿；改寫後仍維持原情境的功能與語域。

## 專案限制與採用判斷
**優點**：專為台灣繁體中文打造，不是簡轉繁；把「AI 味」拆成可檢查模式，並明確處理誤殺；人工確認、保護清單與回歸評測讓改稿可稽核；可用於 Claude Code、Codex、Cursor，以及能讀 Markdown 的 Agent。

**限制**：去掉痕跡不等於建立作者 voice；「更有人味」無法只靠自動評分保證；事實查核不在本 Skill 內；長文逐條列清單會很長，但這是為了保留作者控制權；自動化直改雖方便，對外發布仍應保留最後人審。

**簡短校稿的範圍校準**：38 類檢查清單是欄位清單，不是要每次逐項展開；短稿只列實際命中的問題。

## 標準執行契約

### 觸發與輸入

使用者明確要求此主題，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入與授權，標記缺口、敏感資料與可能的外部依賴。
2. 依本技能的核心流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，並列出引用、未驗證事項、風險與需要人工決策的節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

### 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式或尚待確認的項目。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

### 安全與人工核准

目前風險等級：**low**。預設可先產出分析或草稿，但仍不得代替使用者做外部高影響決策。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。

### 禁止用途
