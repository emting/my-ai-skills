# 談判準備與出牌策略 Skill

> **定位**：在談判前把目標、籌碼、對象、退路與出牌策略整理成可執行劇本，協助使用者避免臨場亂談、過早讓步或被對方框架牽著走。

## 使用情境
- 準備商務合作、採購、報價、合約、薪資、分潤、資源交換或衝突協商。
- 使用者需要知道該開高、開低、開平，或讓對方先出牌。
- 使用者處於弱勢，需要設計議題掛鉤、結盟或備案。
- 談判進行中，需要回應對方的 NO、YES、IF、沉默或黑白臉戰術。

## 不適用情境
- 使用者只是想操縱、欺騙或脅迫對方。
- 沒有任何可交換資源、退路或可談議題。
- 涉及法律、重大財務或勞資糾紛時，仍需專業意見。

## 誠信界線
黑白臉等策略不得假扮權限、捏造籌碼或以威脅施壓。實際讓利與承諾須經使用者人工認可。

## 食譜式目標
| 項目 | 定義 |
|---|---|
| 輸入 | 談判背景、對象、目標、底線、可交換條件、時間壓力 |
| 輸出 | 談判準備表、出牌策略、回應腳本、讓步規則、備案 |
| 數量 | 至少 8 個準備問題、3 種方案、1 個 BATNA（下限不是配額） |
| 格式 | 表格 + 劇本 + 檢查清單 |
| 驗收 | 使用者能直接帶去談判或演練 |

## 核心流程
1. **判斷談判類型**：分配型、整合型、合作型、續約型、危機型。
2. **談判八問**：為什麼要談？想得到什麼？跟誰談？對方為什麼願意談？憑什麼提出要求？有哪些議題可組合？時間站在哪一邊？談不成的退路是什麼？
3. **盤點籌碼**：我有什麼是對方要的？對方有什麼是我需要的？
4. **切割議題**：價格、數量、時間、付款、規格、保固、交付、曝光、資源。
5. **設計出牌**：
   - 開高：定錨與預留讓步。
   - 開低：試探與累積小 yes。
   - 開平：給三種組合方案。
   - 不出牌：讓對方先報條件。
6. **設計回應**：
   - NO：先擋回去，保留空間。
   - YES：讓步幅度遞減、次數不多、速度不快。
   - IF：提出對案，不玩 yes/no 遊戲。
   - 沉默：看誰更需要成交。
7. **黑白臉策略**：設計內部層級、善後角色與破解對方黑白臉的方法。

## Opus 5 世代模型校準
### 不適用情境一律保留
「只是想操縱、欺騙或脅迫對方」與「法律、重大財務、勞資糾紛仍需專業意見」是安全邊界，不是可卸除的品質補強。

### 不要替對方編一個你不知道的內心戲（本 Skill 最大風險）
「對方可能目標」與反應劇本，很容易變成模型用流暢的語言編出一套看起來很確定的對手心理分析。規則：對方目標與底線一律標成**假設**，並同時寫出「要怎麼在現場驗證這個假設」。不要把推測寫得像情報。

### 數量是下限不是配額
若情境單純到只有兩個真實可提方案，就給兩個並說明第三個為何不存在——**湊出來的第三方案在現場會讓你自己亂掉**。

### 籌碼盤點要兩段式
不要下「只列最強的籌碼」。談判中真正能換到東西的往往是那些對你便宜、對對方昂貴的小條件（付款期、交期、曝光、推薦信）。第一輪把所有可交換物全量列出，第二輪再分「我便宜／他昂貴」四象限。

### 0/1 測試是出門前自己核的
五項測試保留，定位是**你帶著這份劇本出門前的人工抽查**。不要追加「輸出前逐項自我檢查」或「再開一個 Agent 模擬對手複核」。真要演練，直接開一段對話讓我扮對手跟你實打。

### 輸出長度
這是**帶去現場用**的文件，長了就失效。第 4、5、6 節（出牌、反應劇本、BATNA）要短到能一眼掃完。不要附送談判理論介紹。

## 標準執行契約

### 觸發與輸入

使用者明確要求此主題，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入與授權，標記缺口、敏感資料與可能的外部依賴。
2. 依本技能的核心流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，並列出引用、未驗證事項、風險與需要人工決策的節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

### 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式或尚待確認的項目。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

### 安全與人工核准

目前風險等級：**high**。需要人工確認。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。
- 此技能只提供分析、草稿與驗證建議，不代表法律、財務、醫療、投資或營運承諾；高風險決策須由合適的人員覆核。

### 禁止用途

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。
- 不得在沒有明確批准、完整上下文與可回溯驗證的情況下執行高影響外部操作。

### 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，先停止執行高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露或輸出無法驗證，保留已完成的安全分析，暫停後續動作並要求人工判斷。
