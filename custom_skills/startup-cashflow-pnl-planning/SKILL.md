# 創業現金流與損益表規劃 Skill

> **定位**：協助個人、副業者與創業者建立年度損益表、現金流情境、業績目標與悲觀底線，用實際數字取代拍腦袋目標。

## 使用情境
- 想規劃明年收入、支出、副業或創業現金流。
- 團隊喊了業績目標，但沒有拆到人、產品、月份與活動。
- 想判斷現金流是否足夠支持試錯。
- 想做 pre-sale 或產品開發前的財務底線評估。

## 不適用情境
- 需要正式稅務、審計、法規或投資建議，需找專業人士。碰到這些問題直接說不確定，不要給一個講得很流暢的答案。

## 食譜式目標
| 項目 | 定義 |
|---|---|
| 輸入 | 收入來源、成本、費用、目標、月份、產品線 |
| 輸出 | 損益表、情境、業績拆解、悲觀底線 |
| 數量 | 至少低／中／高 3 情境 |
| 格式 | 表格 + 決策建議 |
| 驗收 | 能看出現金可撐多久、目標是否合理 |

## 核心流程
1. **建立損益表**：收入 - 成本 - 費用 = 淨利。
2. **情境規劃（上限九種）**：
   - 在職：失業、一成不變、加薪。
   - 副業：低、中、高收入。
   - 創業：低、中、高收入。
3. **打散再集合**：總目標拆到產品、月份、通路、負責人，再加總回來。
4. **避免目標灌水**：不要層層加碼導致 800 萬目標變成 1350 萬工作量。
5. **建立悲觀地板**：用悲觀情境判斷可支撐月數。
6. **Pre-sale 測試**：產品開發前先測市場反應。
7. **主旋律與副歌**：建立年度商業節奏與固定檔期。

## 0/1 測試
| 測試 | 通過條件 |
|---|---|
| 收入可拆 | 收入可拆到單價 × 數量 × 頻率 |
| 成本可見 | 成本與費用不混在一起 |
| 悲觀情境 | 有低收入或失敗情境 |
| 現金水位 | 能算可支撐月數 |
| 目標不喊 | 目標能由下而上加總 |

## Opus 5 世代模型校準
> **這是整批決策框架中錯誤成本最高的一頁。** 其他 Skill 寫錯了是方向偏掉，這一頁寫錯了是真金。以下規則優先於任何輸出完整度考量。

### 沒有數字就不要產生數字（本 Skill 最大風險）
損益表有十二個月、四個欄位，而模型非常擅長把空表填滿。**使用者沒提供的數字一律留空並標「待填」，或集中列在一張「需你提供的數字清單」。** 均攤、行業平均、合理估值都不算資料。一張一半空白但真實的損益表，比一張填滿但一半是推測的有用得多——後者你會拿去做決策。

### 假設要標在數字旁邊，不是寫在文末
每一個推算出來的數字，後面直接標推算依據（例：`180,000（= 15 人 × 12,000，人數為假設）`）。不要把假設集中寫在最後一段，那一段永遠會被跳過。

### 情境數量是下限不是配額
「至少低／中／高 3 情境」是下限。但九種情境（在職／副業／創業 × 低中高）**不是每次都要跑滿**：使用者現在是在職兼副業，就不要產創業三情境。跑不相干的情境只是把真正要看的悲觀地板埋進雜訊裡。

### 風險盤點要兩段式
不要下「只列最大的財務風險」。現金流斷裂很少是單一大支出造成，通常是幾個中型固定支出加收款延遲疊加。先全量列，再排序。

### 不適用情境是安全邊界
「需要正式稅務、審計、法規或投資建議，需找專業人士」一律保留。

### 0/1 測試是交付規格
五項測試保留，定位是**你驗收用的**。特別是「目標不喊」這項——目標能不能由下而上加總，只有你看得出來。

### 輸出長度
使用者要的是**現金能撐幾個月、目標合不合理**。兩句話先講完，表格後附。不要附送財報名詞解釋或記帳方法介紹。

## 標準執行契約

### 觸發與輸入

使用者明確要求此主題，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入與授權，標記缺口、敏感資料與可能的外部依賴。
2. 依本技能的核心流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，並列出引用、未驗證事項、風險與需要人工決策的節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

### 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式或尚待確認的項目。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

### 安全與人工核准

目前風險等級：**high**。需要人工確認。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。
- 對個人、客戶、學生、財務、合約或私有資料採資料最小化；輸出前遮罩識別資訊，避免複製原始敏感資料。
- 此技能只提供分析、草稿與驗證建議，不代表法律、財務、醫療、投資或營運承諾；高風險決策須由合適的人員覆核。

### 禁止用途

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。
- 不得在沒有明確批准、完整上下文與可回溯驗證的情況下執行高影響外部操作。

### 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，先停止執行高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露或輸出無法驗證，保留已完成的安全分析，暫停後續動作並要求人工判斷。
