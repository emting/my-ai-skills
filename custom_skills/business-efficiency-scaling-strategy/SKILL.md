# 商業效率與規模化做局 Skill

> **定位**：用系統化、持續性、規模化三個條件，判斷一個生意、顧問案或產品是否值得投入，並從「做事」升級成「做局」。

## 使用情境
- 想判斷一門生意是否可規模化。
- 顧問、創作者或服務業者想從時薪模式升級成分潤、系統或印鈔機模式。
- 不知道要選什麼客戶、什麼賽道、什麼產品。
- 想把複雜服務拆成 SOP 並複製。

## 不適用情境
- 使用者只想接一次性零工。
- 任務本身無剛需、不可規模化，且使用者不願調整定位。

## 食譜式目標
| 項目 | 定義 |
|---|---|
| 輸入 | 生意描述、客群、交付流程、需求、通路 |
| 輸出 | 剛需 × 規模化四象限、3S 診斷、做局策略 |
| 數量 | 1 個主賽道 + 最多 3 個槓桿點（上限不是配額） |
| 格式 | 表格 + 策略清單 |
| 驗收 | 能判斷要投入、改造或放棄 |

## 核心框架
### 3S
- **系統化**：能否建立 SOP，讓結果可重複？
- **持續性**：流程能否長期運作而不出問題？
- **規模化**：解決的問題是否有大量需求？

### 剛需 × 規模化四象限
| 象限 | 判斷 |
|---|---|
| 有剛需 + 可規模化 | 最佳賽道 |
| 無剛需 + 可規模化 | 可能小賺，需靠流量或娛樂性 |
| 有剛需 + 不可規模化 | 情境式或高客單服務 |
| 無剛需 + 不可規模化 | 零工或低優先 |

## 做局流程
1. 找到有剛需且可規模化的問題。
2. 把服務流程拆成 SOP。
3. 讓 SOP 能持續交付。
4. 找到能放大的通路或夥伴。
5. 從傭兵模式轉成軍火商模式：提供工具、系統、分潤、平台或標準。
6. 選擇可放大的客戶，不服務天花板太低的案子。

```markdown

- 收益方式：

|---|---|---|---|

## 3. 四象限定位

- 規模化程度：

## 4. 做局策略
| 槓桿點 | 做法 | 預期效果 |
```

## 0/1 測試
| 測試 | 通過條件 |
|---|---|
| SOP 可寫 | 能拆出 5 個以上標準步驟 |
| 需求夠強 | 客戶有明確痛點或剛需 |
| 可放大 | 可透過通路、內容、工具或人員複製 |
| 收益槓桿 | 不只靠時薪 |
| 客戶可選 | 能定義不接哪些客戶 |

## Opus 5 世代模型校準
### 「證據」欄不能用推論填
第 2 節 3S 診斷表有證據欄。沒有實際交付紀錄、客戶數或成本資料時，寫「需確認」並列出要看什麼，不要用合理推論填滿。規模化判斷建立在假資料上，比不判斷更危險。

### 槓桿點盤點要兩段式
不要下「只列最大的槓桿點」。新世代模型會照字面執行，把你現在就做得到、但看起來不夠漂亮的小槓桿先刷掉。正確做法：第一輪把所有可能的槓桿點全量列出（SOP、工具、通路、夥伴、定價、客戶篩選），第二輪再用「導入成本 × 放大倍數」排序。

### 「3 個槓桿點」是上限不是配額
真正能改變結構的往往只有一個。寫一個寫透，比湊三個都只寫一行有用。

### 0/1 測試是交付規格
五項測試保留，定位是**你驗收用的**，不是要模型輸出前自我檢查一遍。

### 輸出長度
使用者要的是第 5 節那一句**投入／改造／暫停／放棄**。結論先講，依據後附。不要附送商業模式理論、槓桿概念解釋或知名企業案例類比，除非你問了。

### 範圍鎖定
使用者問一門生意就診斷那門生意。若看出真正該做的是另一門，用一句話說出來，但仍然把原本被問的那門診完。

## 標準執行契約

### 觸發與輸入

使用者明確要求此主題，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入與授權，標記缺口、敏感資料與可能的外部依賴。
2. 依本技能的核心流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，並列出引用、未驗證事項、風險與需要人工決策的節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

### 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式或尚待確認的項目。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

### 安全與人工核准

目前風險等級：**low**。預設可先產出分析或草稿，但仍不得代替使用者做外部高影響決策。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。

### 禁止用途

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。

### 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，先停止執行高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露或輸出無法驗證，保留已完成的安全分析，暫停後續動作並要求人工判斷。
