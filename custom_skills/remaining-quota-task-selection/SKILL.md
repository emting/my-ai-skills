# 剩餘額度任務選擇｜Codex 額度重置前套利框架
> 額度重置不是浪費的藉口，而是啟動長時程高價值任務的訊號。選任務的標準不是「能不能跑完」，而是「產出可不可驗證、風險可不可控」。

## 研究摘要
本 Skill 整理自社群流傳的「Codex 額度重置前燃燒技巧」清單。清單的真正價值不是省錢，而是示範了把 Agent 當成可以連跑數小時的同事，而不是問答機器人。但各點子的價值與風險差異極大：有的具備教科書級的驗收結構（效能改善），有的是無界目標（「極致完美前不要停止」），有的把 Agent 幻覺當決策依據（人生模擬、市場評分）。因此需要分級、排序與安全閘門。

## S1｜觸發條件
### 應觸發
- 「額度快重置了，幫我想想要跑什麼」
- 「剩餘額度不想浪費」
- 「排一個可以跑整晚的長任務」
### 不應觸發
- 手上有明確的當下任務（直接做就好，不需要為了用額度找事做）。
- 額度充足、無時間壓力。
- 為了燒額度而啟動高風險檔案操作。

## S2｜輸入契約
必要輸入：剩餘額度的大致量級、可讓 Agent 無人值守的時間長度、可操作範圍（哪些專案、目錄、系統可被觸碰）。
建議輸入：風險承受度（整理類採「先報告再批准」）、本次偏好（工程產出／系統最佳化／娛樂生成）。

## S3｜執行步驟
### Step 1｜任務分級
| 層級 | 類型 | 特徵 | 範例 |
|---|---|---|---|
| ⭐ 首選 | 元最佳化 | 改一次、未來每次都受益 | 稽核並最佳化自己的 skills／actions |
| ⭐ 首選 | 可驗證工程 | 有明確基準與量測，成果可前後對比 | 效能改善、建立 benchmark |
| ⚠️ 有條件 | 整理稽核 | 有價值但碰檔案／資料，必須加人工閘門 | 專案清理、檔案整理 |
| 🎲 娛樂 | 生成與模擬 | 產出價值不確定，適合真的用不完的額度 | 靈感圖→遊戲、人生模擬、100 個點子 |

### Step 2｜選擇順序
1. 先選元最佳化：唯一會讓「未來每次使用都變好」的複利型投資。
2. 再選可驗證工程：有基準、有量測，跑完就知道值不值。
3. 整理稽核類一律加上人工閘門才啟動。
4. 娛樂生成類放最後，當探索與靈感，不當決策依據。

### Step 3｜套用通用 Prompt 公式
**明確產出物 ＋ 可量測的驗收標準 ＋ 安全邊界（什麼能做、什麼要先問）＋ 回報格式**

### Step 4｜啟動前紅旗檢查
任一項存在就改寫 Prompt：
- 無界目標：「不要停止」「繼續尋找其他可改善的地方」。
- 主觀驗收：「極致完美」「完全一致」。
- 幻覺當事實：要求預測人生、替市場需求評分且不作查證。

## S4｜安全閘門
- 涉及刪除／覆蓋／移動檔案：一律先產出完整稽核報告與建議動作清單，逐項批准後才執行。
- 把「明顯可以處理的直接做」改為「先報告，我批准」。
- UI／動畫類改動：要求前後截圖對比，由人決定保留或還原。
- 人生模擬、市場評分類輸出：標註為「參考素材／自我覺察框架」，不作人生或創業決策依據。
- 課程、計畫類產出：指定寫入可持久追蹤的位置，否則對話結束就散失。

## S5｜輸出格式
### 啟動前：任務卡
每個候選任務輸出：產出物、驗收標準（可量測）、安全邊界（能做／要先問）、回報格式、預估時長與額度量級。
### 事後：成果摘要
- 完成了什麼、量測數據（改善前後對比）。
- 待人工決定清單（未執行的建議動作）。
- 若為生成類：明確標註哪些內容是推測、不可作為決策依據。

## S6｜失敗處理
| 狀況 | 處理方式 |
|---|---|
| 額度不足以跑完 | 要求 Agent 分段存檔中間成果，重置後接續 |
| Agent 陷入完美主義迴圈 | 收回任務，改寫為可收斂目標後重跑 |
| 任務無法量測成效 | 降級為探索任務，縮小範圍或改列清單 |
| 整理類誤刪／誤改 | 事前一律走「先報告再批准」；已發生則從版本紀錄還原 |
| 找不到值得跑的任務 | 直接不跑。為用而用就是浪費，額度作廢不是損失 |

## S7｜任務卡分級對照
| 任務卡 | 分級 |
|---|---|
| Skills／Actions 元最佳化稽核 | ⭐ 首選（複利） |
| App 效能改善 | ⭐ 首選（可驗證） |
| 工作區專案清理計畫 | ⭐ 首選（有閘門設計） |
| 電腦檔案整理稽核 | ⚠️ 需加強閘門 |
| UI 進退場動畫與極簡美化 | ⚠️ 需收斂範圍 |
| 互動式技能學習課程 | ⚠️ 需指定持久化位置 |
| 靈感圖驅動遊戲原型 | 🎲 娛樂（目標需改寫） |
| 人生情境模擬 50 問 | 🎲 娛樂（當自我覺察框架） |
| 理想生活作息設計 | 🎲 娛樂（有實用殘值） |
| 100 個產品點子評分 | 🎲 娛樂（只激發、不篩選） |

## 完成條件
選中的任務必須具備明確產出物、可量測驗收標準、安全邊界與回報格式；涉及刪除／覆蓋／移動檔案的任務一律先產出計畫清單，經人逐項批准後才執行。「找不到值得跑的任務就直接不跑」不得被「額度快到期」的焦慮推翻。

## 標準執行契約

### 觸發與輸入

使用者明確要求「剩餘額度任務選擇｜Codex 額度重置前套利框架」的核心任務，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、授權、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入、授權、敏感資料與可能的外部依賴，先列出缺口。
2. 依上方技能流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，列出引用、未驗證事項、風險與人工決策節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

## 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式、驗收條件與尚待確認事項。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

## 安全與人工核准

目前風險等級：**high**。需要人工確認。本匯入版本為 `instruction_only`，不代表已授權任何外部連接或寫入適配器。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。
- 涉及外部資料時記錄來源、擷取時間與查證限制；將可觀察事實、推論與建議分開呈現。
- 本技能只提供分析、草稿與驗證建議；涉及高影響決策或外部操作時，必須由適當的人員在執行前覆核。

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。

## 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，立即停止高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露、輸出無法驗證或操作不可恢復，保留已完成的安全分析，暫停後續動作並要求人工判斷。

## 關聯技能

本技能與 無 有功能相近或可互補的技能；選擇時以使用者明確需求、資料來源與權限邊界為準，不要平行重複執行相同的高影響操作。
