# AI 資安與 Agent 治理 Skill

> **定位**：為 AI Agent、自動化流程、企業 AI 平台與知識系統建立治理與安全檢查。核心任務是確保 AI 有身份、有權限、有稽核、有煞車，不讓自動化失控。

## 使用情境
- 要導入 AI Agent、企業 AI 平台、RAG、內部知識問答或自動化流程。
- 擔心 Shadow AI、資料外洩、Agent 目標漂移或權限過大。
- 需要設計 AI 身份、權限、審核、日誌與人工核准機制。
- 需要判斷哪些任務可以上雲，哪些必須落地或私有部署。

## 核心風險
| 風險 | 說明 |
|---|---|
| AI 無身份 | 無法追蹤 AI 做了什麼、存取了什麼 |
| Shadow AI | 員工私下把公司資料丟到未授權 AI 工具 |
| 資料外洩 | 訓練、檢索、摘要或代理流程暴露機密資料 |
| Agent 失控 | 從小任務逐步擴大到不該核准的大操作 |
| 權限過大 | AI 能讀或寫超出任務所需的資料 |
| 缺乏稽核 | 無法回溯誰讓 AI 做了什麼 |
| 雲端依賴 | 外部服務停用、降級、限制用途或模型變更 |

## AI 煞車系統
1. **身份**：每個 AI Agent 都要有可識別身份。
2. **最小權限**：只給完成任務所需的資料與操作權限。
3. **操作日誌**：記錄讀取、修改、刪除、通知、API 操作。
4. **人工核准**：金流、人事、個資、對外發佈、刪除、批量修改需人工批准。
5. **範圍限制**：Agent 只能在定義好的任務邊界內行動。
6. **異常停止**：偵測目標漂移、權限越界、成本暴增時停止。
7. **定期審查**：檢查連接器、權限、日誌、模型與資料來源。

## 雲端 vs 落地判斷
| 任務類型 | 建議 |
|---|---|
| 一般編輯、摘要、個人助理 | 可用雲端 |
| 非敏感報告整理 | 可用雲端，但需去識別化 |
| 內部知識問答 | 視資料敏感度決定 |
| 核心流程、產品研發、金融、醫療、資安、學生個資 | 優先私有部署或受控平台 |
| 高風險自動操作 | 必須 human-in-the-loop |

## 品質標準
- 不把便利性放在可追溯性之前。
- 不讓 AI 擁有不必要的寫入或刪除權限。
- 不把個資、商業機密、金融或醫療資料丟給未授權工具。
- 所有高風險自動化都必須設計人工核准與回滾。

## Opus 5 世代模型校準
> **本 Skill 的所有驗證機制一律保留。** 第一節起的身份、日誌、人工核准、停止條件、定期審查都是**治理控制點**，目的是留下給人稽核的痕跡，不是拿來補強模型輸出品質。不得因為新模型自我修正能力變強而刪除任何一項。

### 那要刪什麼？
只刪一種：**要求模型「輸出前再自我檢查一次這份報告」「再開一個 Agent 複核這份風險盤點」這類指令**。這是對模型的品質補強，與內建行為疊加，只增加成本。治理控制點與模型自檢是兩件事，不要混淆。

### 風險盤點必須兩段式（本節最重要）
**絕對不要下「只列高風險項」「只回報嚴重問題」「請保守判斷」。** 新世代模型會照字面執行這類篩選指令，在資安情境下這等於主動漏報漏洞。正確做法：
1. 第一輪：對照「核心風險」表與權限表，**全量**列出所有命中項，包括看起來很小的。
2. 第二輪：再用「可存取資料敏感度 × 可執行操作破壞力」分級。

### 輸出長度
固定輸出格式是欄位清單，不是最低篇幅要求。沒問題的控制項合併一句帶過，有問題的才展開。**但第 3 節權限表不適用此規則：每一個資源都要逐列，權限盤點不能省略。**

### 範圍鎖定
只檢查被交付的那個 Agent 或流程。若發現相鄰系統也有同類風險，用一句話指出並建議另案盤點，不要自行擴大成全公司 AI 治理總體檢。

### 對新世代 Agent 的額外治理項
審查對象若是 Opus 5 世代的 Agent，新增兩個檢查點：
- **子代理生成權限**：新模型傾向多派工。確認子代理是否繼承了不該有的權限，以及是否有並行數上限與成本上限。
- **effort 設定與成本暴衝**：把 effort 等級納入「異常停止」的監控項目；不要用關閉 thinking 來省錢，那會造成工具呼叫外洩為純文字與內部標籤外洩，反而是新的資安面。

## 標準執行契約

### 觸發與輸入

使用者明確要求此主題，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入與授權，標記缺口、敏感資料與可能的外部依賴。
2. 依本技能的核心流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，並列出引用、未驗證事項、風險與需要人工決策的節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

### 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式或尚待確認的項目。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

### 安全與人工核准

目前風險等級：**high**。需要人工確認。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。
- 涉及外部資料時記錄來源、擷取時間與查證限制；將可觀察事實、推論與建議分開呈現。
- 此技能只提供分析、草稿與驗證建議，不代表法律、財務、醫療、投資或營運承諾；高風險決策須由合適的人員覆核。

### 禁止用途

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。
- 不得在沒有明確批准、完整上下文與可回溯驗證的情況下執行高影響外部操作。

### 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，先停止執行高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露或輸出無法驗證，保留已完成的安全分析，暫停後續動作並要求人工判斷。

## 關聯技能

本技能與 無 有功能相近或可互補的既有技能；選擇時以使用者明確需求、資料來源與權限邊界為準，不要平行重複執行相同的高影響操作。
