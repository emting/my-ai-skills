# 信仰 × 科學跨域整合 Skill v1.1｜證據、釋經與牧養安全

> **MOTTO：先查證主張，再處理釋經，最後才建立跨域橋梁。**

## S1｜觸發條件
當任務要把聖經／神學與心理學、哲學、健康、AI、社會科學或文化議題整合成講道、門訓、文章、社群或 Podcast，且包含科學背書、經文應用或牧養建議時啟用。

不適用於單一領域摘要、純格式改寫，或只需查核經文而不需跨域整合的任務。

## S2｜輸入契約
必要輸入：
- 核心問題或原稿
- 經文／信仰命題
- 可辨識的研究來源或明確標示「尚無來源」
- 受眾、用途與輸出格式

### 最低來源門檻
對外宣稱「研究顯示／科學證實／神經科學指出」前，至少確認：
1. 一份原始研究、權威理論來源或官方學術說明；
2. 一份系統性回顧、統合分析或可信綜述；
3. 至少一項方法限制、反證或泛化界線。

若未達門檻，可以整理假設與待查問題，但不得輸出確定的科學背書。若經文脈絡不清，先呼叫「聖經釋義與神學查核 Skill」（`biblical-exegesis-theology-check`）。

## S3｜執行步驟
1. **建立主張台帳**：逐句拆出可被判真假的主張，分類為實證、經文觀察、神學推論、修辭隱喻或牧養建議。
2. **查核實證**：記錄來源、研究設計、樣本、年份、相關／因果、證據強度與限制。
3. **還原經文**：先寫文體、原始受眾、段落功能、救贖歷史位置與經文明說，再談今日應用。
4. **建立五層地圖**：實證發現 → 哲學／價值詮釋 → 經文觀察 → 神學反思 → 牧養應用。
5. **判定關係**：標示相互呼應、存在張力、只可類比、彼此獨立或直接衝突。
6. **檢查類別錯置**：科學構念不等同神學真理；經文應用不等同臨床介入；隱喻不等同作用機制。
7. **修正原稿**：先產內部句級查核版，再產刪除未查證背書的可發布版。

## S4｜安全閘門
- 不把相關性寫成因果，不用單一研究代表整個學界。
- 不寫「科學證明聖經」；歷史或考古事實也只支援其直接可證範圍。
- 不捏造神經科學機制、學者、機構、研究數字、原文詞義或經文背景。
- 不把經文中的亨通、得勝或祝福普遍化成職場、財務、健康與計畫必然成功。
- 不暗示焦慮未改善是因為信心不足、讀經不夠、聚會不夠或奉獻不夠。
- 不把奉獻、服事、順服或屬靈操練寫成換取醫治、成功與開路的條件。
- 不把求助、用藥、治療或危機介入描述為屬靈失敗。
- 對外發布前由人覆核研究來源、經文脈絡、神學立場與牧養語氣。

## S6｜失敗處理
- 沒有研究來源：來源狀態標「不足」，移除科學背書，只保留待查假設。
- 只有單一觀察性研究：使用「相關」語言，不作因果或普遍化結論。
- 找不到可靠跨域橋接：明說只能並置，不硬造共同結論。
- 經文有主要詮釋分歧：並列讀法與依據，交由使用者或牧者確認。
- 去除誇大後核心論點消失：回報「目前不能安全發布」，不要用修辭補洞。
- 涉及自傷、他傷、家暴、虐待或嚴重心理危機：停止內容加工，優先建議當地專業與緊急支援。

## S7｜範例／模板
### 合格例：約書亞記 × SOC
- 實證：較強的連貫感／一致感（Sense of Coherence, SOC）通常與較好的壓力調適相關；證據多為關聯，不能直接推論因果。
- 經文：書 1:1–9 將約書亞的剛強壯膽連於神的應許、律法與同在；經文未直接描述其主觀焦慮程度。
- 橋接：兩者可在「未知中如何形成方向、辨認資源並採取行動」上對話。
- 界線：神的話不等同 SOC 構念；SOC 也不能證明神是否同在。

### 失敗例與修正
| 失敗句 | 問題 | 修正方向 |
|---|---|---|
| 科學證明聖經早就知道 | 混淆認識方法 | 心理學研究與聖經智慧可從不同層次對話 |
| 神的話就是人生的 SOC | 類別錯置 | 神的話可成為理解、資源與意義的信仰來源，但不等同 SOC |
| 晝夜思想會重新編碼大腦 | 無直接研究 | 可說可能影響注意與行動習慣；神經機制需直接研究 |
| 奉獻後神就會為你開路 | 交易式神學 | 奉獻是信仰回應，不是換取結果的條件 |
| 再大打擊都撐得住 | 絕對化與牧養傷害 | 可提升調適；功能受損時仍應尋求專業協助 |

### 隱喻規則
「導航」「避震器」可作教學比喻，但必須標示它們不是 SOC 的正式定義、量表或作用機制。

## 標準執行契約

### 觸發與輸入

使用者明確要求「信仰 × 科學跨域整合 Skill v1.1｜證據、釋經與牧養安全」的核心任務，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、授權、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入、授權、敏感資料與可能的外部依賴，先列出缺口。
2. 依上方技能流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，列出引用、未驗證事項、風險與人工決策節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

## 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式、驗收條件與尚待確認事項。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

## 安全與人工核准

目前風險等級：**high**。需要人工確認。本匯入版本為 `instruction_only`，不代表已授權任何外部連接或寫入適配器。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。
- 涉及外部資料時記錄來源、擷取時間與查證限制；將可觀察事實、推論與建議分開呈現。
- 本技能只提供分析、草稿與驗證建議；涉及高影響決策或外部操作時，必須由適當的人員在執行前覆核。

## 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，立即停止高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露、輸出無法驗證或操作不可恢復，保留已完成的安全分析，暫停後續動作並要求人工判斷。
