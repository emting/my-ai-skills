# 需求壓力測試｜Decision Tree 訪談
> 問決策，不問 Agent 自己能查到的事實；依賴未解決的問題留到下一輪。

## S1｜觸發條件
### 應觸發
- 壓力測試計畫、需求、架構或決策。
- 寫規格前仍有重大分歧。
- 使用者要求「問我問題」「幫我想完整」。
### 不應觸發
- 只需整理已完成的討論。
- 答案可直接從工作區或第一方來源取得。
- 使用者要求立即執行且關鍵決策已完整。

## S2｜輸入契約
必要輸入：要釐清的計畫、決策或想法。
建議輸入：目標、期限、利害關係人、不可改變限制、目前已知選項。

## S3｜執行步驟
1. 建立 Decision Tree：列出核心決策與依賴關係。
2. 將無前置依賴、現在可回答的節點列為 Frontier。
3. 把環境可查的事實交由研究（primary-research），不拿來詢問使用者。
4. 每輪一次詢問完整 Frontier；相依問題延後。
5. 每題包含題名、問題、必要選項與建議答案。
6. 收到回答後更新樹，再計算下一輪 Frontier。
7. Frontier 清空後整理決策、限制、風險與後續動作。

## S4｜安全閘門
- 建議答案必須與問題分開，不能偽裝成已決定。
- 不得替使用者決定價值判斷、預算承諾或對外立場。
- 每輪避免超過可掃讀範圍；相關問題可合併，但不混合相依層級。

## S5｜輸出格式
```text
❓ Q1｜問題標題
問題內容與必要選項。

➡️ 建議：建議答案與理由。
```
使用者可回覆：「Q1 同意、Q2 改成……」。
完成時輸出：
- 已確定決策
- 不可變限制
- 未解問題與負責人
- 主要風險
- 建議下一個 Skill

## S6｜失敗處理
- 使用者回答不完整：只追問仍阻擋下游的節點。
- 研究尚未完成：封鎖依賴該事實的問題，其他 Frontier 照常進行。
- 使用者不想繼續：保存目前決策與未解 Frontier，不硬問完。

## S7｜範例
```text
❓ Q1｜主要讀者
這份系統先服務個人使用，還是團隊共同維護？

➡️ 建議：先以個人使用為主，但欄位命名避免綁死個人習慣。
```

## 完成條件
Decision Tree 的 Frontier 已清空；每個重要決策都有答案、明確延後或指定負責人，且最後輸出決策摘要與未解風險。後續可接 `conversation-to-spec`。

## 標準執行契約

### 觸發與輸入

使用者明確要求「需求壓力測試｜Decision Tree 訪談」的核心任務，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、授權、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入、授權、敏感資料與可能的外部依賴，先列出缺口。
2. 依上方技能流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，列出引用、未驗證事項、風險與人工決策節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

## 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式、驗收條件與尚待確認事項。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

## 安全與人工核准

目前風險等級：**medium**。需要人工確認。本匯入版本為 `instruction_only`，不代表已授權任何外部連接或寫入適配器。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。
- 涉及外部資料時記錄來源、擷取時間與查證限制；將可觀察事實、推論與建議分開呈現。

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。

## 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，立即停止高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露、輸出無法驗證或操作不可恢復，保留已完成的安全分析，暫停後續動作並要求人工判斷。
