# 產品 MVP 驗證與迭代 Skill

> **定位**：在產品開發前，用最低成本驗證痛點、需求強度、使用頻率與付費意願，避免自嗨式創業、過度開發與大量囤貨。

## 使用情境
- 想推出新產品、課程、服務、電商商品、社群方案或 SaaS 功能。
- 還不確定市場是否真的需要。
- 需要設計 MVP、假廣告、預購頁、訪談或 A/B Test。
- 產品已推出，但需要從放棄率、用戶反饋與交付流程找迭代方向。

## 不適用情境
- 已經有大量有效成交數據，只需要規模化投放。
- 高風險醫療、金融、法律產品，不能用假廣告或模糊承諾測試。

## 誠信閘門
假廣告／預購測試必須透明標示「概念測試」與交付狀態；未能交付時的退款／取消條件、資料用途與同意須先確認，不得假裝產品已可供貨或收取不可退款訂金。

## 食譜式目標
| 項目 | 定義 |
|---|---|
| 輸入 | 產品構想、目標客群、痛點、價格、交付方式 |
| 輸出 | 需求四象限、MVP 測試、付費意願驗證、迭代清單 |
| 數量 | 至少 3 個測試方案（下限不是配額）、1 個主驗收指標 |
| 格式 | 表格 + 實驗設計 + 行動清單 |
| 驗收 | 能在低成本下判斷做／不做／改方向 |

## 核心流程
1. **確認市場需求三要素**：痛點、需求強度、付費意願。
2. **需求四象限**：
   - 強需求 × 高頻率：優先開發。
   - 強需求 × 低頻率：高客單價策略。
   - 弱需求 × 高頻率：可替代性高，需小心。
   - 弱需求 × 低頻率：不建議。
3. **設計 MVP**：貼文、預購頁、表單、假廣告、Figma 原型、紙本流程、社群貼文。
4. **微步驟成交**：不要要求使用者一步付費；先讓使用者前進一小步。
5. **測試付費意願**：用預購、訂金、候補名單、價格選項測試。
6. **用戶訪談**：優先訪談付費用戶，其次是放棄用戶。
7. **放棄率分析**：找出流程中掉最多人的環節。
8. **迭代決策**：保留、調整、暫停、放棄。

|---|---|
| 痛點明確 | 能用一句話說明痛點 |

| 指標清楚 | 有明確成功／失敗條件 |
| 用戶反饋 | 至少包含付費或放棄用戶資料 |

## Opus 5 世代模型校準
### 「證據」欄沒有就是沒有（本 Skill 最大風險）
需求四象限有一欄叫「證據」，而這正是整張表唯一重要的欄位。**沒有真實訪談、販售或行為數據時，證據欄寫「尚未驗證」，判斷欄寫「假設」。** 不要用合理推論填滿它。MVP 驗證的全部意義就是區分假設與事實，一旦模型把推測寫得像證據，這份報告就從降低風險變成製造風險。

### 數量是下限不是配額
「至少 3 個測試方案」是避免只想到一種做法。若情境上真正低成本可行的只有兩種，就給兩種。湊出來的第三種測試通常成本高、訊號弱，反而拖慢驗證。

### 卡點盤點要兩段式
第 4 節成交流程拆解不要下「只列最大卡點」。放棄率的真相往往就是兩三個小摩擦疊加。第一輪每一步都列可能卡點，第二輪再排優先序。

### 不適用情境是安全邊界
「高風險醫療、金融、法律產品不能用假廣告或模糊承諾測試」一律保留。假廣告測試本身就有信譽成本，不要因為它便宜就預設推薦。

### 0/1 測試是交付規格
五項測試保留，定位是**你驗收用的**，不是要模型輸出前自我檢查一遍。特別是「付費驗證」這一項，只能由現實世界的付款行為通過，不能由模型宣布通過。

### 輸出長度
使用者要的是第 5 節那一句**做／小規模測／暫緩／放棄**。結論先講，依據後附。不要附送精實創業方法論介紹或 MVP 概念解釋。

## 標準執行契約

### 觸發與輸入

使用者明確要求此主題，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入與授權，標記缺口、敏感資料與可能的外部依賴。
2. 依本技能的核心流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，並列出引用、未驗證事項、風險與需要人工決策的節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

### 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式或尚待確認的項目。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

### 安全與人工核准

目前風險等級：**medium**。預設可先產出分析或草稿，但仍不得代替使用者做外部高影響決策。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。

### 禁止用途

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。

### 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，先停止執行高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露或輸出無法驗證，保留已完成的安全分析，暫停後續動作並要求人工判斷。
