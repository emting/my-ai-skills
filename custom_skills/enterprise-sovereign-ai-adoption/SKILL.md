# 企業主權 AI 平台導入 Skill

> **定位**：協助企業判斷 AI 系統應使用雲端服務、私有部署或企業主權 AI 平台，並設計資料、模型、治理、權限、稽核與流程串接原則。

## 使用情境
- 企業要導入 FedGPT、私有 LLM、一體機、內部 RAG 或多代理平台。
- 涉及商業機密、產品研發、金融、醫療、學校、學生資料或核心流程。
- 需要說明為什麼「資料不出機構、機敏不上雲」。
- 需要為企業 AI 建立權限管理、稽核追蹤與內部術語訓練。

## 核心原則
1. **資料主權**：資料、模型、治理系統、算力盡可能在企業受控環境中運行。
2. **任務分級**：輕量任務可上雲，核心流程與敏感資料需受控。
3. **權限整合**：AI 需接入企業身份與權限系統。
4. **操作可追溯**：記錄誰要求 AI 做什麼、改了什麼、刪了什麼。
5. **企業語言訓練**：讓 AI 理解內部產品、專有名詞、流程與術語。
6. **夥伴生態系**：流程串接與落地通常需要 IT、顧問與業務單位共同設計。

## 任務分級
| 任務 | 建議部署 |
|---|---|
| 一般摘要、非敏感編輯、個人草稿 | 雲端 AI |
| 內部制度問答、部門 SOP 查詢 | 受控 RAG 或私有知識庫 |
| 客服、醫療、金融、學生資料 | 私有部署或企業主權平台 |
| 產品研發、晶片流程、商業策略 | 不建議外部雲端 LLM |
| 自動刪除、核准、寫入核心系統 | 需人工核准與完整稽核 |

## 導入流程
1. **盤點資料與流程**：哪些資料敏感？哪些流程高頻？
2. **分級任務**：雲端、受控、私有、不可 AI 化。
3. **設計權限**：主管、員工、一線角色能看什麼？
4. **建立企業詞典**：產品名、內部術語、流程名稱、常見問答。
5. **設計稽核**：讀取、輸出、刪除、寫入、核准全記錄。
6. **先做 MVP**：挑一個高頻、低風險、價值明確場景。
7. **擴大到多代理流程**：逐步讓 Agent 串接現有系統。

## 品質標準
- 不把所有任務都私有化；需依敏感度與價值分級。
- 不把商業機密、學生個資、醫療或金融資料放入未授權雲端工具。
- 不只談模型，也要談流程、權限、稽核與維運。
- 導入前需有清楚 ROI 或風險降低目標。
- 正式部署仍需企業資安、法務、資料治理及 IT 負責人審查。

## Opus 5 世代模型校準
> **第 5 節上線治理的所有項目一律保留。** 身份、日誌、人工核准、定期審查是治理控制點，目的是留下給稽核用的痕跡，不是拿來補強模型輸出品質。模型變聰明不會讓稽核義務消失。

### 該刪的只有一種
要求模型「輸出評估報告前再自我檢查一次」「另開一個 Agent 複核這份分級」。這類指令與新世代模型的內建自我修正疊加，只增加成本。治理控制點與模型自檢是兩件事。

### 任務分級要兩段式，不要預先篩選
**不要下「只列出高敏感任務」「只給重要的部署建議」。** 新世代模型會照字面執行，把中敏感度但高頻的任務直接略過——而那些往往才是導入 MVP 的最佳起點。正確做法：第一輪全量盤點所有 AI 任務，第二輪再用敏感度分級。

### 範圍鎖定
使用者問某一個場景該不該私有化，就回答那個場景。若判斷整體架構有更根本的問題，用一句話指出並問要不要擴大評估，不要自行把單一場景評估擴大成全公司 AI 戰略。

### 輸出長度
固定輸出格式是欄位清單，不是最低篇幅要求。**架構建議的五層（資料、模型、權限、稽核、Agent 流程）若本次場景用不到某一層，直接標「本案不涉及」並說明原因**，不要為了填滿而虛構層次。資料不足的欄位標「需補資料」，不要用推測值填。

### 新世代 Agent 的額外評估項
若導入對象是 Opus 5 世代的 Agent，任務分級表要多考慮兩件事：
- **子代理生成權限**：新模型傾向多派工。子代理是否會繼承主 Agent 的資料存取權？是否有並行數與成本上限？這應納入第 5 節的定期審查。
- **成本可預測性**：用 effort 等級控成本並納入監控，不要用關閉 thinking 來省錢——那可能造成工具呼叫外洩為純文字與內部標籤外洩，在受控環境下反而是新的合規風險。

## 標準執行契約

### 觸發與輸入

使用者明確要求此主題，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入與授權，標記缺口、敏感資料與可能的外部依賴。
2. 依本技能的核心流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，並列出引用、未驗證事項、風險與需要人工決策的節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

### 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式或尚待確認的項目。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

### 安全與人工核准

目前風險等級：**high**。需要人工確認。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。
- 對個人、客戶、學生、財務、合約或私有資料採資料最小化；輸出前遮罩識別資訊，避免複製原始敏感資料。
- 此技能只提供分析、草稿與驗證建議，不代表法律、財務、醫療、投資或營運承諾；高風險決策須由合適的人員覆核。

### 禁止用途

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。
- 不得在沒有明確批准、完整上下文與可回溯驗證的情況下執行高影響外部操作。

### 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，先停止執行高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露或輸出無法驗證，保留已完成的安全分析，暫停後續動作並要求人工判斷。

## 關聯技能

本技能與 無 有功能相近或可互補的既有技能；選擇時以使用者明確需求、資料來源與權限邊界為準，不要平行重複執行相同的高影響操作。
