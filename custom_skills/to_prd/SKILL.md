# To PRD Skill

## Purpose

將對話脈絡與程式碼理解綜合為 PRD 文件，並保留實作決策、測試決策與範圍界線。

## When to Use

適用於使用者提到以下需求：

- `PRD`
- `產品需求文件`
- `generate a spec`
- 想把目前討論正式化成文件

## Workflow

1. 先讀對話與相關程式碼，理解目前問題、限制與既有行為。
2. 找出會被影響的核心模組、邊界條件與可測試行為。
3. 以 PRD 模板整理問題陳述、解決方案、用戶故事、實作決策與測試決策。
4. 依使用者要求輸出到對話、指定檔案，或準備成 issue 內容。

## Output Template

```markdown
## 問題陳述

## 解決方案

## 用戶故事

## 實作決策

## 測試決策

## 範圍之外

## 補充說明
```

## Output Options

- 直接在對話中輸出 Markdown
- 寫入指定文件路徑
- 整理成可貼到 issue 的內容

## Safety Notes

- 不要憑空捏造需求來源。
- 不要把容易過時的具體檔案路徑硬寫進 PRD 主體。
- 若需要建立 issue 或寫檔，先確認輸出位置。
