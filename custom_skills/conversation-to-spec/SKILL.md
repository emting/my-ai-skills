# Conversation to Spec｜對話轉可執行規格
> 只綜合已討論內容；缺口要標記，不能用重新訪談或腦補掩蓋。

## S1｜觸發條件
### 應觸發
- 將目前對話轉成規格、需求文件或專案定義。
- 把已完成訪談的結果固化成可審查文件。
### 不應觸發
- 需求仍有重大分支未決。
- 使用者只是要會議摘要或逐字紀錄。

## S2｜輸入契約
必要輸入：目前對話、指定來源或已確認決策。
建議輸入：規格保存位置、讀者、是否已有既定模板。

## S3｜執行步驟
1. 讀取完整對話與使用者指定來源。
2. 分離事實、已確認決策、建議與未解問題。
3. 從使用者角度撰寫問題與預期改變。
4. 整理完整使用情境與可觀察驗收條件。
5. 收錄資料結構、權限、流程與人工覆核等已確定決策。
6. 明列範圍外與待確認項目。
7. 逐項回查來源，移除未討論的新增需求。

## S4｜安全閘門
- 不把 Agent 建議寫成使用者已決定。
- 不加入容易過時的頁面 ID、檔案路徑或實作片段，除非它本身就是已確定決策。
- 涉及公開、權限、金額或承諾時，發布前人工覆核。

## S5｜輸出格式
```markdown
## 問題陳述
## 解決方案
## 使用情境
## 已確定決策
## 驗收條件
## 不在本次範圍
## 待確認
## 補充說明
```

## S6｜失敗處理
- Context 不足：產出可確認的部分，缺口放入「待確認」。
- 來源互相矛盾：並列差異，不自行選邊。
- 決策不足以執行：建議回到需求壓力測試（decision-tree-requirement-stress-test）。

## S7｜驗收範例
不佳：「系統要好用、清楚、有效率。」
較佳：「新使用者能在不詢問作者的情況下，從入口頁找到正確資料庫並完成第一筆紀錄。」

## 完成條件
問題、解法、使用情境、已確定決策、驗收條件、範圍外與待確認項目均可追溯至現有 Context，且沒有新增未經同意的需求。需要完整工程 PRD 時改用 `to_prd`。

## 標準執行契約

### 觸發與輸入

使用者明確要求「Conversation to Spec｜對話轉可執行規格」的核心任務，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、授權、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入、授權、敏感資料與可能的外部依賴，先列出缺口。
2. 依上方技能流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，列出引用、未驗證事項、風險與人工決策節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

## 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式、驗收條件與尚待確認事項。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

## 安全與人工核准

目前風險等級：**high**。需要人工確認。本匯入版本為 `instruction_only`，不代表已授權任何外部連接或寫入適配器。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。
- 涉及外部資料時記錄來源、擷取時間與查證限制；將可觀察事實、推論與建議分開呈現。
- 本技能只提供分析、草稿與驗證建議；涉及高影響決策或外部操作時，必須由適當的人員在執行前覆核。

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。

## 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，立即停止高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露、輸出無法驗證或操作不可恢復，保留已完成的安全分析，暫停後續動作並要求人工判斷。

## 關聯技能

本技能與 無 有功能相近或可互補的技能；選擇時以使用者明確需求、資料來源與權限邊界為準，不要平行重複執行相同的高影響操作。
