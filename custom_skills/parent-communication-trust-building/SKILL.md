# 家長訊息回覆與信任建立 Skill｜Moosie 老師版

> **定位**：把老師與行政每天在做的「家長訊息回覆」變成可重複執行的產出流程。本 Skill 只產出**可編修的草稿**，不是自動回覆家長。
> **事實來源**：實際情境與標準口徑以 Moosie 家長溝通 QA 手冊為準。本技能只寫方法，不複製金額、匯款資訊、學生與家長姓名。

## 1. 何時啟用
手上有一則或一串家長訊息需要回覆，且屬於下列任一類：作業與錄音、學習狀況與程度、請假補課調課、學費與行政規範、安親接送與等候、新生諮詢與體驗後追蹤、續報與挽留、客訴與情緒衝突。

**不適用**：對外公開招生文案、官網與廣告素材、品牌事實查詢。這些走各自的專門頁面。

## 2. 輸入（沒有就問，不要編）
| 必填 | 家長原訊息全文、孩子年級與班型、發訊者角色（老師／行政／主任） |
|---|---|
| 有更好 | 近期課堂觀察、作業回傳狀況、過去與這位家長的溝通脈絡 |
| 絕不推測 | 金額、梯次、補課名額、退費規則、當期公告內容、師資背景細節 |

## 3. 執行步驟
1. **分類**：判斷屬於哪一大類。一句話帶過，不要輸出分析過程。
2. **判風險等級**：
   - 🟢 一般：作業、練習方法、單純告知 → 直接產草稿。
   - 🟡 需謹慎：進度焦慮、作業量、孩子情緒、適應不良 → 先同理，再給具體觀察與做法。
   - 🔴 需人工：金額、退費、跨期補課、師資疑慮、客訴、安全事件 → 仍產草稿，但開頭標明「需行政／主任確認後才能發送」。
3. **抓一項具體觀察**：從輸入資料裡找出至少一個真實、具體的孩子表現。找不到就留空格標「請填入你的課堂觀察」，**不得自行編一個進步**。
4. **依四段結構寫草稿**（見第 4 節）。
5. **過紅線檢查**（見第 6 節），有觸線就改寫。
6. **輸出**：一則可直接貼到 LINE 的草稿 ＋ 一行「需你確認的事項」。

## 4. 回覆四段結構
1. **同理**：接住家長的負擔或擔心。不責備孩子，也不責備家長。
2. **具體觀察**：講孩子實際發生了什麼，不是「有進步」這種空話。
3. **做法**：老師接下來會怎麼做，或家長在家可以怎麼做，要能執行。
4. **下一步**：明確的時間點或後續動作，讓家長知道這件事有人在追。

學習評估類另有固定順序：具體肯定 → 需要加強處 → 老師會怎麼協助 → 家長可以怎麼配合。

## 5. 語氣規範（用正面示範，不用禁止清單）
| 情境 | ❌ 容易寫成 | ✅ 應該寫成 |
|---|---|---|
| 作業寫太久 | 請家長多督促孩子準時完成 | 我們先保護孩子的學習動力，這週改成減量增質，先鎖定核心單字與錄音 |
| 家長嫌貴 | 平均下來一堂課其實不貴 | 我們不是用一堂多少錢計算，而是一期完整的能力規劃：閱讀理解、寫作架構、口說表達與文法調整 |
| 班級人數調整 | 之後人數變多，費用會比較便宜 | 這不是增加人數，而是學習模式升級；孩子需要更多討論與合作的階段才會進入互動班型 |
| 家長婉拒 | 這次優惠只到本週喔 | 完全沒關係，等孩子之後更有興趣接觸英文，歡迎再來一起學習 |

## 6. 安全紅線（不可協商，全數保留）
- **不承諾未確認的事**：補課名額、跨期安排、時段調整、優惠適用與否，一律先確認再回。
- **不報金額**：所有費用以行政正式報價為準。草稿中金額一律寫成 `＿＿＿（請填入行政報價）`。
- **不比價、不催促、不製造焦慮**、不主動電話推銷。
- **不承諾學習成果**，不與其他孩子比較。
- 師資疑慮、客訴、退費、安全事件屬信任議題，**不用簡短文字硬回**，草稿要建議改約電話。
- 涉及個資的內容先去識別再處理。

## 7. Opus 5 世代模型校準
### 空白比推測有價值
這是本 Skill 最容易失效的地方。家長訊息回覆有固定四段結構，新世代模型會忠實地把每一段填滿——包括它其實不知道的「具體觀察」。一則讀起來很完整、但觀察是編的草稿，比一則留白的草稿危險得多，因為你會直接送出去。**沒有的資料就留空格，不要補**。

### 數量是上限不是配額
不要求「至少給三個建議」。一則家長訊息通常只需要一個明確的下一步；湊出來的第二、第三個建議會稀釋重點，也會讓家長不知道該做哪一件。

### 輸出長度要匹配情境
草稿是要貼進 LINE 的。🟢 一般類三到五句即可；🔴 高風險類可以長，但長的是說明與同理，不是套話。不要為了顯得慎重而加開場白與結尾致意。

### 分類與回覆分兩段做
判斷情境時全量看完整串訊息，不要看到第一句就決定類別。家長常在一則訊息裡同時問時段和費用，只回其中一件會讓對方覺得被敷衍。

### 這是草稿，人工關卡一定保留
第 6 節的紅線與「需行政確認」標記不是模型自檢，是**你發送前的檢查點**。不要因為模型宣稱檢查過就跳過。

## 8. 交付標準（發送前人工抽查）
- [ ] 具體觀察是真的，不是模型補的
- [ ] 沒有出現未經確認的金額、名額或時段
- [ ] 四段結構完整，且第一段是同理不是說明
- [ ] 語氣沒有責備、催促或推銷感
- [ ] 🔴 類已標明需行政／主任確認


## 標準執行契約

### 觸發與輸入

使用者明確要求此主題，或輸入與本技能描述高度相符時才啟用。先確認目標、受眾、上下文、資料來源、限制條件與希望的輸出格式；未提供的資訊不得自行補成事實。

### 執行順序

1. 盤點輸入與授權，標記缺口、敏感資料與可能的外部依賴。
2. 依本技能的核心流程逐步處理，將事實、推論、假設與建議分開。
3. 產出可直接審閱的結果，並列出引用、未驗證事項、風險與需要人工決策的節點。
4. 執行輸出前檢查，確認沒有虛構證據、洩漏敏感資料或超出使用者範圍的動作。

### 輸出契約

至少提供：

- **結果或草稿**：依使用者要求產出分析、策略、腳本、內容、清單或計畫。
- **假設與限制**：明確標示資料不足、未驗證推論與適用範圍。
- **驗證紀錄**：列出使用的來源、檢查方式或尚待確認的項目。
- **風險與下一步**：指出人工核准點、低成本驗證方式與可恢復的後續行動。

### 安全與人工核准

目前風險等級：**high**。需要人工確認。

- 先確認任務目標、輸入來源、使用授權、範圍與輸出格式；缺少關鍵資訊時先列出假設並提出最少必要問題。
- 不得捏造事實、數據、案例、評價、客戶反饋、媒體報導、認證或研究來源；無法驗證的內容必須標示為假設或待驗證。
- 只使用使用者提供或明確授權的內容；不得繞過登入、CAPTCHA、付費牆、存取控制或第三方服務限制。
- 外部服務一律採唯讀或草稿模式；發送、發佈、建立、更新、刪除、部署、交易、預算變更與權限變更前必須取得明確人工批准。
- 對個人、客戶、學生、財務、合約或私有資料採資料最小化；輸出前遮罩識別資訊，避免複製原始敏感資料。
- 此技能只提供分析、草稿與驗證建議，不代表法律、財務、醫療、投資或營運承諾；高風險決策須由合適的人員覆核。

### 禁止用途

- 不得用於未授權存取、憑證收集、冒充他人、垃圾訊息、操縱或規避平台政策。
- 不得把未經授權的第三方內容、個資或機密資料重新發布到公開服務。
- 不得在沒有明確批准、完整上下文與可回溯驗證的情況下執行高影響外部操作。

### 停止條件

若使用授權、資料來源、範圍、關鍵數字、身份或外部操作權限無法確認，先停止執行高影響部分並回報缺口。若發現來源互相矛盾、任務目標漂移、敏感資料暴露或輸出無法驗證，保留已完成的安全分析，暫停後續動作並要求人工判斷。
